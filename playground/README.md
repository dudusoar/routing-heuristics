# Routing Heuristics Playground

Interactive Streamlit interface for learning and testing the routing-heuristics package.
The playground is meant to expose the solver as a usable workflow: define a problem,
configure ALNS, run the solver, inspect the result, and save local experiment artifacts.

## Quick Start

From the repository root:

```bash
uv pip install -e ".[dev]"
uv pip install streamlit
streamlit run playground/app.py
```

The app opens at `http://localhost:8501` by default.

## Current Scope

The playground currently contains two tabs:

- `Quickstart`: generate a synthetic PDPTW instance, configure ALNS, solve, and inspect routes.
- `Problem Variants`: compare relaxed, standard, and strict constraint presets.

Implemented user-facing capabilities:

- Synthetic instance generation with seed control.
- ALNS configuration for iteration count, vehicle count, start temperature, cooling rate, segment length, and battery capacity.
- Solver execution through the package APIs.
- Cost, feasibility, route count, route visualization, and route detail displays.
- Local experiment export to `runs/`.

Known limitations:

- Convergence history is not exposed by the current ALNS runner, so the convergence panel is a placeholder.
- CSV upload, saved-run replay, and interactive real-map selection are not implemented yet.
- The app is an exploratory learning surface, not a polished benchmark runner.

## Project Layout

```text
playground/
|-- app.py          # Streamlit entry point
|-- README.md       # Playground usage and maintenance notes
`-- tests/          # Playground-specific test artifacts when needed
```

Related repository areas:

- `contracts/`: checks that playground-facing behavior matches actual package behavior.
- `tests/`: unit and integration tests for the package.
- `tutorials/`: notebook-based examples that can feed future playground features.
- `runs/`: local experiment output generated by the app; ignored by Git.

## Learning Model

The design principle is: learn by playing, not by reading code line by line.

The app should teach three layers:

- Interface layer: what a valid instance looks like and what a solution contains.
- Pipeline layer: how generation, configuration, solving, and evaluation connect.
- Mechanism layer: how constraints and ALNS parameters change solution quality and feasibility.

When adding features, prefer small interactive slices that make one of those layers visible.

## Development Notes

Use the package APIs directly from `vrp_toolkit`; avoid duplicating solver logic inside the app.

For behavior that the user can observe in the UI, add or update a contract test when practical. Useful contracts include:

- Same seed and same config should reproduce the same result.
- A displayed feasibility claim should match the solution object's feasibility check.
- Displayed objective values should match the package calculation.

Keep local outputs under `runs/` and generated map/data artifacts under ignored paths.

## Troubleshooting

If Streamlit cannot import `vrp_toolkit`, reinstall the package from the repository root:

```bash
uv pip install -e .
```

If the default port is busy:

```bash
streamlit run playground/app.py --server.port 8502
```

To run contract checks:

```bash
pytest contracts/ -v
```
